# Run the site 24/7 for free on Render (no credit card)

This is the most reliable **no‑credit‑card** way to give your colleague an always‑on URL. Render's free web service hosts
the site, the API and the daily refresh; a free **Neon** Postgres keeps the data safe. Neither asks for a card, and
Render can deploy a **private** repo (no need to make it public). ~15 minutes.

**What runs here and what doesn't:** Render's free instance has 512 MB RAM — enough for the app, but *not* for Chromium.
So the API‑based automation runs normally (ATTOM property/owner data, delinquent taxes, GIS, valuation), while the two
browser‑based sources (Delaware C‑Track liens, Montgomery UJS judgments) become a **manual capture step** here. See
[Filling in liens/judgments](#filling-in-liensjudgments) for how to automate those from your own PC when you want to.

---

## Step 1 — Free database (so data survives restarts) — do this first

Render's free instance spins down when idle and comes back with an empty disk, so the data must live in an external
database. Neon's free tier is perfect and needs no card.

1. Sign up at **https://neon.tech** (free, no card) and create a project.
2. Copy the connection string. It looks like `postgresql://user:pass@ep-xxx.neon.tech/neondb?sslmode=require`.
3. Change the start `postgresql://` to **`postgresql+psycopg://`** (keep the `?sslmode=require`). Save it for Step 3.

## Step 2 — Create the Render service from the blueprint

1. Sign in at **https://render.com** with your GitHub account (no card for the free plan).
2. **New → Blueprint**, and pick the `ReaLTOR` repository. Render reads `render.yaml` automatically. *(Private repo is
   fine — authorize Render's GitHub access when asked.)*
3. Render lists the environment values it needs. Click **Apply / Create**.

## Step 3 — Enter the secrets

When prompted (or afterwards under the service's **Environment** tab), fill in the values marked "enter in dashboard":

| Key | Value |
|---|---|
| `USI_SITE_PASSWORD` | The password your friend types to open the site. |
| `USI_SECRET_PROVIDER_ATTOM_API_KEY` | Your ATTOM API key. |
| `USI_DATABASE_URL` | The `postgresql+psycopg://…?sslmode=require` string from Step 1. |

`USI_MASTER_KEY` is generated by Render automatically and kept stable, and the username defaults to `demo`. Save; Render
builds and deploys (first build ~5–10 min).

## Step 4 — Open it and share

- Render shows a URL like `https://upset-sale-intel.onrender.com`. Open it and sign in with **`demo`** and your password.
- Send your friend the URL, `demo`, and the password. They can upload sale lists, run **Autopilot**, and review results
  any time.

**Free‑plan note:** the service sleeps after ~15 minutes with no visitors; the next visit takes ~30–60 s to wake it. The
data itself is safe in Neon.

## Filling in liens/judgments

On Render the browser sources can't run, so after Autopilot they show as **capture tasks** (a "search C‑Track" / "search
UJS" to‑do). Two ways to complete them:

1. **Manually in the UI** — open the task, run the search on the official site, paste the results; the app parses them.
2. **From your own PC, fully automatic** — run the app locally pointed at the *same Neon database* with the browser turned
   on, then click Autopilot; your PC does the Chromium searches and the results appear on the live site for everyone:
   ```bash
   cd backend
   python -m venv .venv && .venv\Scripts\activate      # macOS/Linux: source .venv/bin/activate
   pip install -r requirements.txt -r requirements-browser.txt -r requirements-postgres.txt
   python -m playwright install --with-deps chromium
   set USI_DATABASE_URL=postgresql+psycopg://...        # the SAME Neon string; PowerShell: $env:USI_DATABASE_URL="..."
   set USI_BROWSER_AUTOMATION=true
   set USI_MASTER_KEY=...                                # copy the value Render generated (Environment tab) so secrets match
   set USI_SECRET_PROVIDER_ATTOM_API_KEY=...
   python scripts/serve.py
   ```
   Open `http://localhost:8000`, run Autopilot on the project; liens/judgments fill in and sync to the Render site because
   both share the Neon database. Close it when done — the live site keeps everything.

*(If you want the browser automation running 24/7 without your PC, that needs a host with ~1 GB RAM and a card — an Oracle
Always Free VM, see [DEPLOY_ORACLE.md](DEPLOY_ORACLE.md).)*

## Updating and troubleshooting

- **Update to new code:** Render auto‑deploys on every push to the default branch. Or **Manual Deploy → Deploy latest**.
- **ATTOM says "not configured":** `USI_SECRET_PROVIDER_ATTOM_API_KEY` is missing/misspelled in Environment.
- **Data disappeared:** `USI_DATABASE_URL` isn't set (Step 1/3), so it fell back to the disposable local file.
- **Password not accepted:** confirm `USI_SITE_PASSWORD` is set and `USI_AUTH_MODE` is left at `local`.
